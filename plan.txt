ARCHITECTURE CIBLE — MVC
=====================================================================
/models
   db.py                  -> connexion SQLite, exécution de requêtes
   schema.sql              -> définition des tables (v1, modifiable)
   migrations/              -> scripts .sql versionnés pour faire évoluer le schéma 
                              sans tout casser
   pos_model.py, transactions_model.py, oos_model.py, hvc_model.py, 
   reference_model.py      -> accès données + nettoyage/normalisation propre à 
                              chaque entité. Aucune page n'écrit de SQL directement.

/controllers
   dashboard_controller.py, performance_controller.py, conquete_controller.py, 
   oos_controller.py, map_controller.py
   -> orchestrent : appellent les models, appliquent les filtres (y compris le 
      filtre HEURE pour performance_controller), calculent les KPIs via kpis.py, 
      préparent les données prêtes à afficher
   kpis.py                 -> calculs de KPI, purs, testables, indépendants de 
                              Streamlit
   exclusion.py             -> LA règle d'exclusion globale, unique, utilisée par 
                              tous les controllers concernés
   geo.py                   -> clustering géographique (utilisé uniquement par 
                              map_controller, non prioritaire)

/views
   dashboard_view.py, performance_view.py, conquete_view.py, oos_view.py, 
   map_view.py, settings_view.py
   -> uniquement du rendu Streamlit : reçoivent des données déjà prêtes du 
      controller, affichent. Pas de logique métier, pas de SQL. Pages volontairement 
      légères (peu de sections, peu de KPIs par écran).

/services
   export_service.py        -> UN SEUL point d'export pour toute l'app :
                              - to_csv(df)
                              - to_excel(df, styles) : reconstruit le fichier Excel 
                                cellule par cellule (openpyxl) en respectant 
                                EXACTEMENT la mise en forme conditionnelle affichée 
                                à l'écran (couleurs de seuil, ligne de total, 
                                en-têtes) — jamais un df.to_excel() brut
                              - to_image(df, styles) : génère un PNG fidèle au 
                                tableau tel qu'affiché (mêmes couleurs, mêmes 
                                libellés, même mise en page), en généralisant 
                                l'approche SANS Chrome déjà développée dans 
                                variations_hvc.py — pas dataframe_image
                              Toutes les vues utilisent uniquement ce service pour 
                              leurs boutons CSV / Excel / Image, y compris les 
                              exports groupés (ZIP multi-fichiers par cluster/
                              territoire) déjà présents ailleurs.

/config
   settings.py               -> seuils métier externalisés (grille perf, seuils 
                              OOS, seuil gros transfert, etc.), modifiables sans 
                              redéploiement

/ingestion
   ingest.py                 -> lit les fichiers Excel/CSV sources et alimente 
                              SQLite (remplace storage.py + data_loader.py + partie 
                              de supabase.py). Nettoyage (téléphones, types de 
                              transaction) fait UNE SEULE FOIS ici, à l'insertion.

/tests
   -> tests unitaires sur controllers/kpis.py, controllers/exclusion.py, et 
      services/export_service.py

Fichiers à supprimer après migration (uniquement après confirmation explicite de 
ma part) : storage.py, data_loader.py, conquete_territoire_v3.py, dataframe_image 
(dépendance Chrome), et toute fonction dupliquée une fois centralisée 
(format_amount, style_perf, load_perf_folders, _load_excluded_to_phones, etc.).
